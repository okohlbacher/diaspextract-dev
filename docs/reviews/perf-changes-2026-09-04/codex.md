- **1 — Critical, silent-results/UB: CHANGE 3 is NOT OUTPUT-NEUTRAL without a stronger parameter guard.** With `delta_rt = std::numeric_limits<double>::denorm_min()`, one fragment at RT `1.0`, and a precursor at RT `1.0`, the original exact gate passes. The new code computes `inv = inf`, then `(1.0 - 1.0) * inf = NaN`; `bucketOf()` reaches `(int)NaN`, which is undefined behavior. It may reject the fragment, overflow while calculating `dq`, or crash. Positive subnormal values are not excluded by the current `delta_rt >= 0` validation. See [FragRt::bucketOf/build](/Users/kohlbach/Claude/speXtract/src/DIAPseudoSpectra.cpp:2239).

- **2 — Critical, silent-results/UB: finite RTs can create the same CHANGE 3 failure.** For fragment RTs `{-DBL_MAX, +DBL_MAX}` and an ordinary positive `delta_rt`, `hi - lo` becomes infinity. Widening sets `inv` to zero, after which the high fragment computes `inf * 0 = NaN` and again casts NaN to `int`. Both fragment RTs survive the current `isfinite` filter. This is pathological acquisition data, but it disproves the unconditional neutrality claim. Disable the quantized rejection whenever `delta_rt`, `inv`, `span`, or the computed bucket coordinate is non-finite.

- **3 — CHANGE 3 is otherwise mathematically safe for normal finite inputs.** If `delta_rt > 0`, all arithmetic remains finite, and `span * inv` is bounded, the effective bucket width is at least `delta_rt`. Exact-passing pairs therefore differ by at most one mathematical bucket; allowing two covers boundary rounding. Widening cannot make buckets narrower.

- **4 — The CHANGE 3 clamps are safe on both ends within that finite domain.** A precursor below `rt0` that is within `delta_rt` of a fragment can only be within approximately one bucket of bucket zero. At the upper end, real fragment buckets are limited to approximately 65000, and an exact-passing precursor can lie less than one effective bucket beyond the maximum. It therefore cannot reach the 65535 clamp while its fragment remains over two buckets away. The 535-bucket margin also prevents ordinary rounding from overflowing `uint16_t`.

- **5 — NaN/inf RTs do not reach CHANGE 3 through the current caller.** Fragment RTs are removed at [the finiteness filter](/Users/kohlbach/Claude/speXtract/src/DIAPseudoSpectra.cpp:3480), and every precursor scoring path checks finite RT/IM. Negative finite RTs are safe. `delta_rt == 0` is also neutral: all buckets become zero and the exact equality gate remains authoritative. Negative tolerances are rejected by configuration; if invoked directly, the unchanged exact test rejects every finite pair. Empty fragment sets return earlier, and a normal single-element set is safe.

- **6 — CHANGE 3 always increases resident storage.** It retains the original 8-byte RT array and adds roughly `2N` bytes plus vector metadata for `q`; nothing is removed. That cost is absent from the memory ledger. It is a bandwidth optimization, not a memory optimization. Against the stated 867-billion visits it is plausibly worthwhile, but sparse windows or runs with few precursors can be slower because they pay two construction passes and an extra branch without enough repeated scans to amortize them.

- **7 — The CHANGE 3 build is O(n), as claimed, but it is an additional full O(n) pass.** The first pass copies RTs and finds extrema; the second writes quantized buckets. The prior code populated `frag_im` and `frag_rt` together in one pass. Complexity is unchanged, constant work is not.

- **8 — CHANGE 1 is OUTPUT-NEUTRAL in the two actual merge sites.** Reserving capacity cannot alter elements, offsets, source order, or trace order. No successful-run input was found that changes spectra. In the band merge, every nonempty integer-detector store has `bins.size() == inten.size()` because detection resizes `bins` after each appended span. In the post-split chunk merge, every chunk store has empty `bins`. Thus `any_bins` is correct here.

- **9 — Reserving `bins` to the summed `inten` size cannot be too small under the existing invariant.** `absorb()` can pad only to the current intensity base and then append at most `other.inten.size()` bins, so its required size never exceeds total intensity size. In the band merge it is exactly the required size; after valley splitting `any_bins` is false. See [TraceStore::absorb](/Users/kohlbach/Claude/speXtract/src/DIAPseudoSpectra.cpp:297).

- **10 — CHANGE 1 does not guarantee a lower peak.** Both `reserve()` calls allocate the complete destination while every source vector is still live; the old loop grew the destination while freeing each source immediately after absorption. For example, with 48 equal sources whose capacities are near twice their sizes, upfront reserve can have all source capacity plus the full destination live simultaneously, whereas incremental growth may free enough sources before its largest allocation. RSS depends on allocator lazy commitment, but allocator capacity and `bad_alloc` risk can rise. The comments claiming the reserve necessarily eliminates a “2x” transient are too strong; only HWM measurements can establish the result.

- **11 — `TraceStore::absorb()` itself is unsafe for arbitrary mixed binful/binless sources, although neither current merge triggers it.** Absorb a binful source followed by a nonempty binless source: `inten` grows but `bins` does not. A later `!bins.empty()` test followed by indexing the second trace’s offset reads beyond `bins`. The reserve condition does not repair that latent invariant. Either require all nonempty sources to agree about bins or resize `bins` through every binless source once bin storage has begun.

- **12 — CHANGE 2 is OUTPUT-NEUTRAL in the current execution context.** The single overload clears its result and immediately calls the same `detectElutionPeaks_` routine used by the vector overload. Clearing is safe because children are converted before the next call. The surrounding task executes inside the outer OpenMP region, so the patched old vector path was the serial nested loop shown in [the lock-free patch](/Users/kohlbach/Claude/speXtract/patches/openms-epd-lockfree.patch:7), preserving parent and child order.

- **13 — OpenMS confirms there is no cross-trace numerical state in CHANGE 2.** `scan_time`, smoothing window, Savitzky–Golay filtering, extrema, FWHM, and optional noise/SNR are computed from the current trace only in [ElutionPeakDetection.cpp](/Users/kohlbach/Claude/OpenMS/src/openms/source/FEATUREFINDER/ElutionPeakDetection.cpp:380). SNR filtering is disabled. The only collection-wide operation is the separately invoked `filterByPeakWidth()`, which this path never calls. Hoisting the EPD object is safe because detection does not accumulate mutable per-call state.

- **14 — `MassTrace(vector)` and `MassTrace(list)` are output-equivalent.** Both copy the same `Peak2D` sequence into the internal vector without sorting or centroid calculation; the vector constructor merely performs the copy directly. Centroid fields retain identical defaults, and IM is explicitly set afterward. See [MassTrace.cpp](/Users/kohlbach/Claude/OpenMS/src/openms/source/KERNEL/MassTrace.cpp:28).

- **15 — CHANGE 2 has a definite reallocation regression for highly split inputs.** The old conversion reserved `split.size()` output `Trace` records after EPD. The streamed version reserves only the parent count, `hi - lo`. A chunk where every parent produces three or more children forces geometric reallocations and moves of `Trace` records. Streaming still likely wins overall memory, but this part is strictly slower and transiently heavier. Tracking child counts or reserving additional capacity would avoid it.

- **16 — CHANGE 2’s new memory accounting is invalid.** `MemGuard g_mt` is constructed only after the entire trace loop, when almost all measured parent/child lifetimes have ended. Its byte calculation also omits the reused `pk` buffer, vector capacities, smoothing buffers, and EPD temporaries. `MassTrace mt(pk)` copies `pk`, so both parent representations coexist throughout detection. Consequently the ledger cannot substantiate the claimed peak reduction and materially undercounts the live streamed payload at [lines 1132–1172](/Users/kohlbach/Claude/speXtract/src/DIAPseudoSpectra.cpp:1132).

Strict verdicts: **Change 1 — OUTPUT-NEUTRAL, memory improvement unproven. Change 2 — OUTPUT-NEUTRAL, with measurable allocation/accounting defects. Change 3 — NOT OUTPUT-NEUTRAL until non-finite/intermediate-overflow cases fall back to the exact gate.**
