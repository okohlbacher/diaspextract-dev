## The tiled reader's contract
For the exactness bound (any tiling of cells, any thread count, bit-identical to the one-tile run at the same P) the tiled reader must satisfy, per run and per cell:

1. Grid: the cell-edge list, cycle (frameSpacing) and split_scan_time are computed ONCE from the full run-level MS1 frame list -- the same reader path that skips raw-empty frames (MzPeakStreamLoad.h:364), not the tdf Frames table -- by the rule at src/spextractor.cpp:3392-3399 (edge k = rts[k*n], n = round(P/cyc), remainder < n/2 joins the last cell), before any tile is read; the header stamp is a round-trip-exact record (S2) used for verification, never as the source. An MS2 frame belongs to cell k iff T_k <= rt < T_{k+1} (lower_bound on the frame time, :4145); the MS1 frame at T_k belongs to cell k.

2. Frame set and payload: for every cell the reader delivers exactly the frames the streaming loader appends today -- raw-non-empty MS2 frames of the window in RT order, INCLUDING frames whose picked count is 0 -- with bit-identical picked (tof, intensity, imq) arrays and per-frame calibration factors; gate with slabDigest_ (:884, order-preserving) per cell against the whole-run slab sliced by sliceFrames, not with the sorted traceDigest_.

3. Frozen detector scalars (M2): per-window band edges bnd and band count nb are run-level, identical in every tile, stamped; the band assignment is total (asserted superset or clamped outer bands); the tof index geometry may be per cell (exact). Noise, snr, mass_ppm, delta_im, min_len, msr, IM/mz quanta, the TOF axis and calibration table are run-level as today.

4. Detection is per cell on the cell's slice alone (seeds, visited, frame_live, tof index per cell), traces rebased by the cell's first frame's index in the FROZEN full window frame table (S5), absorbed in (cell, band) order; no halo, no cross-cell state.

5. Frozen scoring support (S5): the window's frame table is the full run-level table (all frames of the window's group), used[f]=1 for every frame, G := F, pdense sized F_full, so nearest_local is a pure function of the two frame tables and a fragment span read outside the tile reads 0 exactly as in the whole run.

6. Pass 1 and inference are whole-run: MS1 traces detected per cell on the same grid (step 4) and absorbed into one global store, then the MS1 FWHM (:3456-3492), the content sort (:3524-3531), inferPrecursors_ (greedy over the complete sorted set) and the im-veto run over the identical concatenated set BEFORE pass 2 of any tile; ms1_store's frame table is whole-run so p_tr.frame0+k (:2849) indexes the same table.

7. Carry-over and deferral (step 3): tile k receives from cell k-1 the children with rtOf >= T_k - 2*delta_rt (record + span) prepended to frag_traces before the canonical sort, and scores precursors with rt in [T_k - delta_rt, T_{k+1} - delta_rt); require P >= 2*delta_rt or carry transitively.

8. Resident-set-independent downstream: the splitter guard is in.empty() (S3); the fragment sort is a total content order with the tie count logged (S4); the 500-cap tie-break (:3044-3049) then depends only on content; the header's run-total fields use the placeholder pattern.

9. Gates: G1 on the real reader (D at P=300, 1/2/3 tiles x threads {8,100}, SPECTRUM DATA IDENTICAL), per-cell failure detectors (G_live == F, no nearest_local == -1 for a scored precursor point, no owned trace outside its cell, no equal-key sort neighbours -- or count them), plus the two e2e fixtures.

## Disagreements settled
1. Pure-function (refuted) vs rebase-and-order (not refuted) on whether a cell's parents are a pure function of the slice: both are right about the code, they answer different questions. The detector body is a pure function of (slice, bnd, tlo, thi, nb, options) -- verified: sliceFrames preserves peak order so the `a > b` seed tie-break is shift-invariant, visited/frame_live/seed segments/tof index are per cell, the tof index geometry is provably output-neutral for any tlo <= min tof. bnd/tlo/thi/nb are WINDOW-level from the resident slab (:4116-4137), so the claim holds for every run this commit can make (the whole window is always resident) and fails for the first tile-local slab. Settled as M2: not a defect of this commit's runs, a precondition of the tiled reader, and the freeze must be total (assert or clamp) because bandOf/buildTofIndex corrupt on tof < tlo.

2. Rebase lens ('more memory at P>0') vs cost lens ('within ~3 B/peak, merge peak unchanged'): both correct in their regime (K=2-3 up to +3 B/peak, K>=4 lower; merge x2 arena unchanged); memory only, no output effect. Note N1.

3. Edges lens ('the equal-key sort residual is not tile-independent') vs rebase lens ('not introduced or widened') vs judge.md ('tile-independent'): the edges lens is right that std::sort's order on equal keys depends on the whole sort input, which differs per tile; the rebase lens is right that this commit cannot create cross-cell ties (rtOf lies inside each trace's own cell). judge.md's 'tile-independent' is wrong. Settled as S4 (total content order).

4. Edges lens ('a probe pass cannot prove the tiled bound') vs the plan's use of the probe: settled in the edges lens's favour (M3). The probe injects the whole run's tlo/thi/G from its own log and keeps whole-run MS1 and resident neighbours; it can validate only the MS2-detection half per cell, and only with exact stamped edges and halo 0.

5. Cost lens ('this commit's P>0 output is an asymmetric cut; the judge's isotope-lanes-cut-at-the-same-frame describes the post-step-4 state') vs judge.md's Bound: the cost lens is right -- MS1 is whole-run at :3433-3441, the Pearson arithmetic at :2940 gives ~1/sqrt(2) for an apex cut against a whole XIC, and step 4 changes the near-line output. Settled as N2: no code change here, but no P>0 pin or G2 price from this commit is final.

6. Pure-function lens's 'latent OOB' finding: confirmed by reading (:1089-1090 -> size_t(-1) index at :1104/:1108; :1045 wrap; :1169 unguarded), latent today because tlo is the window min and every cell is a subset. Folded into M2 rather than a separate item.

7. Cost lens's header-stamp finding (S1) and the unrecorded gate (M1): confirmed by reading (:3384-3404, :3968-3969, :4549-4550; git show --stat; no tile:rt_sec in test/ bench/ harness/; no BASELINE row) -- nobody disputed them; classified as stated.

Overall: the mechanism (cut, slice, per-cell detection, (cell,band) merge, rebase of exactly the three absolute fields, byte-identical identity arm, thread invariance) is correct as written. The commit does not yet back the option text's 'bit-identical however the cells are grouped into tiles', because the band partition and the scoring support are window-derived and steps 1/3/4 are outstanding; the contract above is what closes it.
