  ## 1. Exactness: is per-cell detection a pure function of the slice?

  ## 5. What the gate cannot see

  The probe gate — cell-aligned ranges, halo 0, frozen edges/G, MS1 whole-run — **does prove per-cell detection exactness** (given §1, a cell's output depends on nothing the probe varies, and the frag-dump comparison is cell-clean). It does *not* prove tiled-mode output identity. Concretely still unimplemented vs the judge's bound:

  1. **Frozen frame table / G / nearest_local** (judge step 1). `wst.setFrames` still takes the *resident* slab (4110); `buildFragStats` computes `nearest_local` over resident window frames (1700-1710) and G from resident spans (1691-1694, override only via the probe's window file, 4311-4313). Consequence: at halo 0, a core precursor within `delta_rt` of a probe edge misses boundary fragments, and any precursor whose MS1 XIC extends past the range gets `nearest_local = -1` where the whole run maps a frame — **the probe cannot gate spectra near range edges at all**. At this commit the only sound gate is detection-level (parent dump per interior cell), not spectrum-level; G1's `SPECTRUM DATA IDENTICAL` needs steps 1+3 first.
  2. **tlo/thi freeze is load-bearing and probe-only**: 4116-4117 derives band edges from the resident slab. A real tile reader holding only a tile's frames would derive *different* edges and different detection — the probe passes only because `SPEXTRACTOR_WINDOW_FILE` overrides them. The tiled reader **must** route through a whole-run (tlo, thi) (and the same `nb`/`bnd` derivation), or the gate's premise is void.
  3. **The offset rebase is a trap for step 1** (should-fix): `t.frame0 += cut[ci]` (4203) is exact only because the window's frame table *is* the resident slab and cells are contiguous in it. The judge's step 1 replaces that table with the frozen metadata table (including frames the loader dropped), where a cell's frames are **not contiguous** and the rebase must go through `rt_index` values (plan C5 — judge.md:13 says "not an offset"). Step 1 landing on this code would silently mis-rebase every off-cell-zero trace. Leave a marker at 4203 or an assert that `wst.rt_index` is the slab's own table. **Should-fix** (no effect today; bites exactly once, at the next step).
  4. **Carry-over/deferral** (judge step 3) and **pass 1 per cell** (step 4): absent as advertised; the probe keeps MS1 and the whole window's cells in one process, so cross-tile window assembly ((cell, band) order across tile boundaries — required by §2) and boundary-child scoring are entirely unexercised.
  5. **What tiled mode must preserve**, precisely: identical picked-peak bytes per cell frame; run-level cell edges (metadata MS1 table, half-open `lower_bound` assignment); frozen per-window (tlo, thi) and `nb`; whole-run `rtAxis` (span_s, frameSpacing, rt_index all read it); rt_index-based rebase onto the frozen frame table; global (cell, band) absorb order; `delta_rt` carry-over before the canonical sort; G/frozen `used` for the Pearson support; MS1 whole-run until step 4 lands.

  Also on the exactness claim itself — **should-fix, doc**: the `tile:rt_sec` help (1891) promises bit-identity "however many threads run", but with `perf:trace_bands=0` the band count is `ceil(threads / windows)` (3847-3850 → 4104 → 4119), and banding changes detection (per-band `visited`, core-only seeding). The judge's bound is explicitly scoped "at the existing fixed-thread determinism" (judge.md:21); the option text overstates it. One sentence fixes it.
