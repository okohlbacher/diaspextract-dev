**Run 1 vs run 2.** Run 1 produced the same digests for R3, R3a, R3b, R3c (3bc037d1), R7b and R7 (a2adbd99) as run 2, and the same R6 output size, with exit 0 everywhere. Its FAIL verdicts on those rows came from one log line, which the driver's case-insensitive marker `error|refus|...` counted as an error. The line is:

`[foreign] assembly:foreign_precursor_weight 0.0 (...): ...; mean m/z error of the 51384272 matches -0.443 ppm`

That line exists only when foreign removal is on, and it is on by default since 1.6.0. Run 2 excludes exactly that line with `NOT_ERR`. Re-scored on run 1's logs, the corrected marker gives 0 on all 13 rows that count error lines: the 6 `$RESET` rows were 0 already, and the 7 default rows drop from 1 to 0. **Any later gate driver must carry the NOT_ERR exclusion**; copy it from `gate_D_160rc1b.sh`.
